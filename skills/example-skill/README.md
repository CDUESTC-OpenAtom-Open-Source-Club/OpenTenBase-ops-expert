# Example Skill 模板

> 📝 **Skill #11** — 这是新建 Skill 时的参考模板，展示了标准 Skill 的完整结构

---

## 这个文件有什么用

当你需要创建一个新的 Skill 时，可以：

1. 复制 `example-skill` 目录
2. 按本模板填写各项内容
3. 修改 `SKILL.md` 中的 name、description 和流程
4. 在 `references/` 中添加详细的参考资料
5. 在 `scripts/` 中放置可复用的脚本

---

## 标准 Skill 目录结构

```
skills/<skill-name>/
├── README.md           ← 你正在看的这个（可选，但推荐）
├── SKILL.md            ← 核心描述文件（必需）
├── references/         ← 详细知识文档（可选）
│   ├── concept-a.md
│   └── command-guide.md
├── scripts/            ← 可执行脚本（可选）
│   ├── main.py
│   └── helper.sh
└── assets/             ← 配置模板等资源（可选）
    └── config-template.ini
```

---

## SKILL.md 必填字段

```yaml
---
name: <skill-name>               # 唯一标识（小写+连字符）
description: <一句话描述>         # 触发词和用途说明
version: 1.0.0                   # 版本号
user-invocable: true             # 是否可被用户直接触发
---
```

---

## SKILL.md 核心章节

| 章节 | 必须包含 |
|------|---------|
| **何时使用** | 触发场景、用户意图 |
| **默认目标** | Skill 的核心行为和输出 |
| **处理流程** | 分步骤的标准化流程 |
| **程序辅助** | 脚本调用方式（如有） |
| **输出模式** | 成功/失败/异常时的输出格式 |
| **红线** | 禁止自动执行的操作 |
| **必读参考** | references/ 文档索引 |

---

## 参考文档写作规范

`references/` 中的文档应该：

- 📖 **解释"为什么"** — 不仅告诉用户做什么，还要解释原理
- 📋 **提供示例** — 每个命令都附带预期输出
- ⚠️ **标注风险** — 危险操作必须明确警告
- 🔗 **关联索引** — 相关文档之间互相引用

---

## 脚本写作规范

`scripts/` 中的脚本应该：

- 🐍 **Python 3** 或 **Shell** 编写
- 📝 **带参数解析** — 用 `argparse` 或 `getopts`
- 📖 **带帮助信息** — `--help` 输出用法说明
- ✅ **返回明确的退出码** — 0=成功，非0=失败
- 🔍 **错误信息清晰** — 不把异常吞掉
- 📄 **日志输出到 stderr** — 便于管道处理

## 新建 Skill 检查清单

创建新的 Skill 时，确保完成：

- [ ] `SKILL.md` 填写完整（name / description / version / 流程 / 红线）
- [ ] `README.md` 撰写完成（触发场景 / 典型使用 / 命令示例）
- [ ] 必要的 `references/` 文档
- [ ] 可复用的 `scripts/` 脚本（如果需要）
- [ ] 在 `AGENTS.md` 中添加任务路由
- [ ] 在 `TOOLS.md` 中登记 Skill 和依赖
- [ ] 在真实环境验证成功路径和失败路径
